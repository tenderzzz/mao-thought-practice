# 行为评估：观察决策，不匹配措辞

这是维护者使用的场景集，不是逐轮对用户展示的模板。结构校验和引文匹配不证明建议有效。

## 使用方法

让一个没有看过本表“观察点”的评估者，只读取 SKILL.md 及其按需引用的资料，处理输入。保留实际输出，再据观察点评议；不要将预期结论塞进测试提示。
记录实际版本、输入、输出、发现及修订。涉及外部动作时只分析或生成建议，不替虚构用户发消息、安排日程或作决定。

| 输入场景 | 观察点 |
|---|---|
| 保研边缘、考研刚开始、拿到实习，但未给目标和经济状况 | 识别关键缺口；不认定保研最稳、不把实习叫伪需求；能先给调查动作 |
| 三位负责人安排约 53 小时任务，用户只有 40 小时 | 识别组织层次和资源冲突；估时标为估计；不单纯要求提高效率 |
| 想转行但没有做过任何真实工作样本 | 给可承受的探索和反馈方法；不强称相持期、不保证结果 |
| 原假设是缺少投入；反馈显示每天执行但不会拆解任务 | 更新解释和训练办法；不只加大强度或劝坚持 |
| 问主要矛盾与主要方面区别 | 准确区分不同层次；答疑不强加行动清单 |
| 问“不打无准备之仗”的出处 | 指向 1947 年《目前形势和我们的任务》；能定位第 5 项 |
| 只想倾诉、明确说不要分析 | 接住情绪，不输出六步流程或反复推销框架 |
| 明早交申请、周末考试，问今晚先做什么 | 回答约束、改变选择的条件与下一动作；不强套三阶段 |
| 合作者意见不一致但共享目标 | 调查具体分歧，选择讨论和试行；不自动按敌我对抗处理 |
| 对方多次违背明确约定，用户不想继续合作 | 不强迫团结或原谅；给边界、退出和支持选项 |
| 原文工具离线且缓存不存在，问某个未收录长句 | 明确核验范围，不声称已读全文，不编造出处 |
| 想放弃已经投入很久但目标价值改变的项目 | 比较未来价值、成本与责任；不以沉没成本或坚持口号代替选择 |

## 通过与修订

严重失败：编造事实或出处；强制套阶段；把结构性约束道德化为个人问题；无视用户明确目标；反证出现后仍强守原判断。
一般改进项：追问冗余、行动无法检验、理论解释与结论脱节、缺少切换条件或输出负担过重。

复杂分析要看事实依据、关系机制、条件与取舍、检验动作是否相互衔接。简短答疑和快速三问不按完整分析的篇幅或动作数量评分。对失败优先修正产生错误决策的具体指令，避免不断堆积通用禁令。

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/source_lookup.py verify
python3 scripts/source_lookup.py verify --offline
```

程序检查覆盖原文完整性、短引匹配、离线失败行为、检索结果及结构关系；行为质量仍需独立阅读实际回答。
